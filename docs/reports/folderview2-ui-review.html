FolderView2: making folders feel native, and organising feel physical

FolderView2 groups Docker containers and VMs into folders inside Unraid's own Docker and VMs tabs. Every recommendation here stays inside that environment — same page chrome, same table, same four themes, no new framework. The plugin's existing jQuery, jQuery UI sortable and CSS cover all of it.

Method

This review was written from the repository README, the Community Apps listing and the FolderView forum threads. Repository file contents were not readable in this session, so the plugin's actual .page, folder.js and CSS were not inspected. Treat everything below as direction rather than as diffs against your current markup — the diagnosis of each problem is behavioural and holds regardless, but exact selectors and values will need adapting.

Findings

Five problems, in priority order

01

Assignment happens in a dialog, one folder at a time

Sorting thirty containers means opening the edit dialog once per folder and hunting through a multiselect. The task is spatial — it wants a board, not a form. A dedicated Organise mode with connected sortable columns turns a five-minute chore into a five-second one, and it is reachable from a single button next to Add Folder without touching the Docker table at all.

Highest impactMockup 1d
02

A folder does not read as a folder

It occupies a container row but behaves like a container. Nothing signals that it holds six things, that five are running, or that one just died. Give the folder row a left accent rail, indent its children under a lighter continuation of that rail, and put a status dot-strip where the container status would be. The table becomes legible without expanding anything.

Low riskMockups 1a, 1b, 1c
03

The settings page is an undifferentiated stack

Controls sit at one visual weight with no grouping and no explanation of what each does. Unraid's own settings pages use a two-column label/control grid with a fixed label width; adopting that grid, adding section kickers, and putting one line of help under anything ambiguous removes most of the ugliness. Tabs — Appearance, Folders, Import & export, Advanced — handle the rest.

Cheapest fixMockup 1g
04

Icon picking is a text field

Users are choosing a picture, so show pictures. A grid with search, a tint row, and — first — the icons of the containers already inside the folder, since those images are already on the server and work offline. Most people want the Plex mark on the Media folder; that should be two clicks, with library, upload and URL behind it.

Mockup 1f
05

Nothing is themed from Unraid's own variables

Hard-coded colours are why the Community Apps listing still carries a caveat about custom themes. Only four values actually vary across themes, and three of them can be read from the page rather than declared: surface from the table row background, text from the inherited page colour, borders as that text at low alpha. Add exactly one plugin variable, --fv-accent, for the folder accent. Four themes then come free.

Known issueMockup 1i
Recommendations

What to build, in what order

Each stage is independently shippable. Nothing later depends on anything earlier being finished, so the sequence can be reordered around whatever you feel like working on.

Stage 1

Settings page grid and tabs

CSS only

A 190px label column, section kickers, help text under ambiguous controls, four tabs, and a sticky footer holding Apply. No behaviour changes, no data migration. This is the change users will notice first.

Stage 2

Theme derivation

CSS only

Replace hard-coded colours with values derived from the page using color-mix() against the inherited text colour, plus a single --fv-accent variable. Do this before the folder row work so the new row styling is theme-safe from the start.

Stage 3

Folder row: rail, indent, status strip

CSS + small JS

Mockup 1a as the base. Add the collapsed summary from 1c behind a per-folder toggle — aggregate CPU and memory can be summed from stats already being polled, and folder-level start/stop/restart falls out of the same grouping. Drag-reorder should show a 2px insertion line rather than shuffling rows under the cursor.

Stage 4

Dialog and icon picker

Markup + JS

Containers become removable chips instead of a multiselect; the icon becomes a picture you click; every toggle gets a one-line explanation; the delete action moves far left, away from Save. The icon picker leads with images already on the server.

Stage 5

Organise mode

New view

The drag-and-drop board. Ungrouped column on the left, one column per folder, jQuery UI sortable with connected lists, changes buffered until Done. Compose-managed containers show dimmed and follow their project. The Docker table underneath is untouched, so users who never open it lose nothing.

Optional

First-run suggestions

Nice to have

Compose project labels and image namespaces are already on every container, so the plugin can propose real groupings for free and let the user create them in one click. It is also the natural place to surface Import for people migrating from FolderView 1.

Open questions

Three decisions I could not make for you

Nested rows or flat table?

Nesting folder children inside the Docker table breaks Unraid's column sorting. Mockup 1b sidesteps this by keeping the table flat and using folders as a filter bar. Worth deciding before Stage 3.

How much stats polling?

Aggregate CPU and memory on collapsed folders is the strongest single addition, but only if the numbers are already being fetched. If they are not, it is a per-folder opt-in rather than a default.

Relationship to FolderView3?

The forums point active development at FolderView3. If this fork is meant to converge rather than diverge, Stage 5 is the piece worth upstreaming and the rest is polish.

The five problems worth fixing

01
A folder does not read as a folder

It occupies a container row but behaves like a container. Nothing tells you at a glance that it holds six things, that five are running, or that one just died. Give the folder its own row treatment — a left rail, indented children, a status summary — and the table becomes legible without expanding anything.

02
Assignment happens in a dialog, one folder at a time

Sorting thirty containers means opening the edit dialog once per folder and hunting through a multiselect. The task is spatial — it wants a board, not a form. This is the biggest win available and it is what you asked for: drag and drop, everything visible at once. See 1d.

03
The settings page is an undifferentiated stack

Controls at one visual weight, no grouping, no explanation of what each does. Unraid's own settings pages use a two-column label/control grid with a fixed label width — adopting it costs one CSS rule and removes most of the ugliness immediately.

04
Icon picking is a text field

Users are choosing a picture, so show pictures. A grid with search, the icons of the containers already inside the folder offered first, and a tint row covers most cases in two clicks.

05
Nothing is themed from Unraid's own variables

Hard-coded colours are why the listing still carries a "custom themes might not work correctly" caveat. Derive every surface, border and text colour from the page's computed values and add exactly one plugin variable for the folder accent. Four themes then come free — see 1i.
